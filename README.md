# dG Albums

Weekly project status updates for dataGambit, in the style of Atlassian Atlas, running entirely on GitHub.

**Site:** https://datagambit-co-za.github.io/dGAlbums-gh/

## How it works

Everything is stored in GitHub Issues in this repo. There's no server or database.

| In the app | On GitHub |
|---|---|
| Project | An issue with the `project` label, created with the **New project** form. Edit the issue to change the details. |
| Client | An issue with the `client` label, created with the **New client** form. A client can have any number of projects. Close the issue to move it to *Former clients*. |
| Project's client | The project form's **Client** field: the client's name (as on the Clients page) or its issue number. Leave it blank for internal projects. |
| Status update | An issue with the `status-update` label, created with the **Status update** form. A bot links it to its project and closes it. |
| Comments and reactions | Comments and reactions on the project or update issue. |
| Follow a project | React with 👀 to the project issue's first post. Owners and contributors follow automatically. |
| Mark a project done | Post a **Done** update, or close the project issue. Close it as *not planned* to archive it. |

The site is plain HTML, CSS and JavaScript in `site/`, with no build step. It reads `site/data.json`. The **Build and deploy** workflow (`.github/workflows/site.yml`) runs whenever an issue or comment changes, and also every hour (reactions don't trigger workflows). It reads the issues into `site/data.json` and publishes the `site/` folder to GitHub Pages.

| Path | What it is |
|---|---|
| `site/index.html`, `site/app.js`, `site/styles.css` | The website |
| `site/data.json` | Generated by the workflow; not committed |
| `dev/sample-data.json` | Example data for trying the site locally |
| `scripts/` | Node scripts the workflows run: build the data, process updates, send emails |
| `.github/ISSUE_TEMPLATE/` | The New client, New project and Status update forms |
| `config/people.json` | The team |

Because the repo is public, anyone with a GitHub account can open issues. The site only shows content from people in `config/people.json`, org members and repo collaborators.

### Emails

| Workflow | When | What |
|---|---|---|
| Weekly update reminders | Fridays 09:00 SAST | Emails each owner whose project has had no update for 5 days. If someone has no email configured, they get an @mention on the project issue instead. |
| Weekly digest | Mondays 08:00 SAST | Emails each person the past week's updates on the projects they follow, plus any projects that missed their update. |

Both can be run from the **Actions** tab with **Run workflow**. Manual runs default to a dry run, which shows the emails in the run summary instead of sending them.

## Setup

1. **Pages:** Settings → Pages → Build and deployment → Source: **GitHub Actions**.
2. **People:** add the team to `config/people.json`:
   ```json
   { "people": [{ "login": "github-username", "name": "Full Name", "team": "Analytics" }] }
   ```
3. **Secrets** (Settings → Secrets and variables → Actions):
   | Secret | Example |
   |---|---|
   | `PEOPLE_EMAILS` | `{"github-username": "name@datagambit.co.za"}` |
   | `SMTP_HOST` | `smtp.office365.com` or `smtp.gmail.com` |
   | `SMTP_PORT` | `587` |
   | `SMTP_USER` | `albums@datagambit.co.za` |
   | `SMTP_PASS` | an app password for that mailbox |
   | `MAIL_FROM` | `dG Albums <albums@datagambit.co.za>` |

   Email addresses go in a secret, not in `people.json`, because the repo is public. Until `SMTP_HOST` is set, the email jobs only do dry runs.
4. **Recommended:** Settings → Moderation options → Interaction limits → *Limit to prior contributors* or *collaborators only*, so strangers can't open issues.
5. Push to `main`. The first run creates the `project` and `status-update` labels.

## Making it private later

The plan is to move to a private repo with the site on Cloudflare Pages, behind Cloudflare Access (sign-in limited to @datagambit.co.za). All the data lives in the issues, so only the `deploy` job in `site.yml` changes. Projects, updates, comments and reactions move with the repo. Until then, everything here is public, so don't post anything confidential.

## Local development

Copy in the sample data and serve the folder (opening `index.html` directly won't work, because browsers block loading `data.json` from a file):

```bash
cp dev/sample-data.json site/data.json
python3 -m http.server 4317 -d site
```

Then open http://localhost:4317. To use the real data instead (needs Node.js):

```bash
GITHUB_TOKEN=<token> GITHUB_REPOSITORY=datagambit-co-za/dGAlbums-gh node scripts/build-data.mjs
```
